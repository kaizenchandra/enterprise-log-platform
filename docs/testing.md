# Executable verification

Run the local stack first. These suites use synthetic data. The system suite interrupts the local backend and storage
services; use an isolated Compose project, never a shared deployment.

```bash
JAVA_HOME=$(/usr/libexec/java_home -v 21) mvn -f backend/pom.xml verify
python3 scripts/system_test.py
cd frontend
CHROMIUM_PATH=/path/to/Chromium npm exec playwright test
npm run typecheck
npm run build
```

The system suite acquires development tokens from Keycloak, registers a unique source, checks
authentication/authorization/input budgets, sends duplicate events, verifies tenant isolation, stops OpenSearch, kills
the backend, recreates Kafka and verifies previously unindexed Kafka data appears after restart. It checks fail-closed
Kafka downtime and retries with immutable identities after restoration. It then runs a four-client, 100-event batch,
2,000-event closed-loop workload, waits for search reconciliation, and writes measured results to
docs/results/system-test.json. This small experiment measures this workstation and workload, not maximum supported
capacity.

Browser tests use a short-lived private fixture under /tmp generated by the system suite. They interact with the real
session form, explorer, XSS-safe message rendering, event details, saved searches, analytics, source lists and SSE; they
also check unauthenticated and foreign-origin requests. No backend responses are mocked. Set CHROMIUM_PATH for an
existing compatible browser or install the Playwright-managed Chromium with `npx playwright install chromium`.

Indexer unit tests cover mixed 201/429/400 bulk outcomes, selective retry and acknowledgment failure during quarantine.
Spring offsets are committed at batch completion; an unknown outcome/rebalance can replay a whole poll. Create IDs make
previously indexed items conflict harmlessly. Quarantine publish failure prevents completion. Quarantine itself is at
least once; operator tools must deduplicate its content-hash IDs. Quarantine replay UI, per-tenant retention and repair
authorization are still required.

These tests are not Testcontainers suites and do not establish multi-AZ durability. They do exercise real
Kafka/PostgreSQL/OpenSearch containers. High-scale load, disk corruption, region failure, full OTLP semantic
compatibility, notifications and archive restore need separate evidence.

Additional real-stack suites:

```bash
python3 scripts/archive_test.py
python3 scripts/policy_test.py
python3 scripts/notification_failure_test.py
python3 scripts/query_benchmark.py
```

Run sequentially: archive tests refresh the short-lived browser fixture, policy tests set/reset the demo tenant hot
policy, and notification failure tests stop/restore only the local receiver. The root workflow
`.github/workflows/log-platform.yml` executes these checks and uploads results; its CI execution remains unverified
until pushed/run.
